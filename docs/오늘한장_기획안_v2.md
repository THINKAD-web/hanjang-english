## 0. 결정

앱을 어린이 영어 / 성인 / 일본어로 쪼개지 않는다. **코어는 하나, 팩만 늘린다.**

- 지금 출시하는 것: 어린이 영어 ㄱ 8장
- 지금 심어 두는 것: 브랜드, 스키마의 `language`·`audience`, 팩 단위 경로, 홈의 팩 슬롯
- 지금 만들지 않는 것: 일본어·중국어 콘텐츠, 성인 화면, 언어 토글, 계정·결제

한 번에 두 제품을 출시하지 않는다. 두 제품을 **전제하고 뼈대만 깐다.**
뼈대 작업은 PR 하나(PR3a)로 끝낸다. 그 이상 커지면 범위가 넘친 것이다.

## 1. 큰 틀

```
오늘 한장
 ├─ 어린이
 │    ├─ 영어 ㄱㄴㄷ          ← 1호 팩 (한장영어)
 │    ├─ 일본어 あ            (예약)
 │    └─ 중국어              (예약)
 └─ 성인
      ├─ 영어 출장·미팅       (2호 후보)
      ├─ 일본어 여행·업무     (3호 후보)
      └─ 중국어              (예약)
```

어린이/성인은 별도 앱이 아니라 **라이브러리(팩 슬롯)** 다.
"아이 영어 + 부모 일본어"를 한 가족이 같이 쓰는 구도는 **가설**이다. 2차 KPI(같은 계정의 두 번째 팩 요청)로 검증한다.

## 2. 포지션

| 층 | 이름 | 역할 |
|---|---|---|
| 앱 | 오늘 한장 | 하루 한 장 습관 |
| 팩 | 한장영어 등 | 언어 × 연령 × 커리큘럼 |
| 단위 | ㄱ, travel … | 팩 안의 목차 |
| 장 | ㄱ-03 | 오늘 할 일 |

외부 카피 예:
- 앱: 오늘 한장 — 하루에 한 장.
- 팩: 어린이 영어 · ㄱ부터.
- 성인 추가 시: 오늘 한장 — 아이 영어, 내 일본어.

결제자는 성인이므로, 어린이 전용 앱으로 포지션을 고정하지 않는다.

## 3. 제품 원칙

1. 하루 한 장. 끝.
2. 한 장은 8분 안에 끝난다. (목표 범위 6~10분)
3. 목차는 그 팩의 단위다. (어린이 영어 = 자음, 성인 영어 = 상황, 일본어 = 행)
4. 틀린 것만 내일 다시 나온다.
5. 부모/본인 요약은 한 화면이다.
6. 언어가 바뀌어도 장 포맷은 같다.
7. 어린이·성인은 페이지를 두 벌 만들지 않고 스킨만 나눈다.
8. **장 순서는 엔진이 정한다.** URL이나 버튼으로 건너뛸 수 없다.

## 5. 공통 스키마

이미 main에 머지된 한장영어 스키마를 **이름만 일반화**한다. 새로 설계하지 않는다.

### 5-1. Pack (`pack.json`)

```text
Pack
  id              // "en-kid-giyeok"
  language        // en | ja | zh
  audience        // kid | adult
  title           // "어린이 영어"
  brandLabel      // "한장영어"
  unitKey         // "giyeok"
  unitLabel       // "ㄱ"
  lessonCount     // 8
  status          // live | soon
```

### 5-2. Item (`items.json`, 팩 공용 뱅크)

현재 `words.json`의 Word를 일반화한다. 뱅크 구조는 유지한다 (L7·L8처럼 앞 장 단어를 다시 쓰기 때문).

```text
Item
  id              // "g-grape" (팩 안에서 고유)
  kind            // word | phrase | hanzi
  text            // grape / Could you hold on a second? / いただきます
  reading?        // kana, pinyin — 없으면 생략
  meaningKo
  emoji? image? audio?
  imageable       // false면 그림 문항 출제 금지
  tags[]          // 약점 집계용: ["gr"], ["-g"], ["k"]  (현재 sound 필드를 배열로)
```

### 5-3. Lesson (`lessons/NN.json`)

```text
Lesson
  id, packId, dayNo, title
  focus           // { label, lines[2] }  오늘의 소리 / 오늘의 패턴 / 오늘의 한자
                  //   (현재 soundIntro를 이름만 변경)
  itemIds[8]
  sentences[2]    // { text, reading?, meaningKo, itemIds[] }
  quiz[5]
  reviewed
```

### 5-4. Quiz

```text
Quiz
  type            // picture_choice | meaning_choice | fill_blank | listen_choice | ox
                  //   (코드에 이미 있는 이름 유지. 이름 바꾸는 작업은 하지 않음)
  targetItemId    // ★ 필수. 오답 큐·약점 집계의 기준
  prompt / sentence / statement
  options[3]
  answer
```

### 5-5. 5유형 규칙

- 기본: 5유형을 1개씩 출제한다.
- **예외:** 장 안에 `imageable: true` 아이템이 하나도 없으면 `picture_choice` 자리를 `listen_choice` 또는 `fill_blank`로 대체한다. 성인 문장 팩은 대부분 이 경우에 해당한다.
- `content:check`는 팩의 `audience`와 `kind`를 보고 이 예외를 허용한다.
- 주관식 쓰기는 모든 팩에서 제외한다.

예시
- 어린이 영어: `grape` / 포도
- 성인 영어: `Could you hold on a second?` / 잠깐만 기다려 주시겠어요?
- 일본어: `いただきます` / reading `itadakimasu` / 잘 먹겠습니다
- 중국어(이후): `谢谢` / reading `xièxie` — 성조 필드는 그때 추가

## 6. 라우팅과 콘텐츠 경로

```text
/                             오늘 홈 (현재 팩 + 슬롯)
/packs                        내 팩 + 추가 (준비 중 표시)
/packs/[packId]               팩 안 목차 (ㄱ 3/8, 자음 줄)
/learn/[packId]                오늘 장 — 엔진(decideToday)이 lesson/review를 결정
/learn/[packId]/[lessonId]     이미 끝낸 장 다시 보기 전용 (진도·도장 반영 없음)
/parent                       부모·본인 요약
/account                      PIN, 프로필, (이후) 구독
/sheet                        → /learn/en-kid-giyeok 로 리다이렉트
```

- 오늘 장 URL에는 장 번호를 넣지 않는다. 번호를 넣으면 주소만 바꿔서 잠긴 장으로 건너뛸 수 있다.
- `[lessonId]` 경로로 잠긴 장에 접근하면 `/learn/[packId]`로 되돌린다.
- 디버그 `?date=`는 모든 경로에서 유지한다.

콘텐츠 경로:

```text
/content/en/kid/giyeok/pack.json
/content/en/kid/giyeok/items.json
/content/en/kid/giyeok/lessons/01.json … 08.json
/content/en/adult/travel/…      (예약, 파일 없음)
```

팩 목록은 `/content/packs.json` 한 파일로 관리한다 (id, status, 경로).

## 7. 홈 정보구조

### 7-1. 홈 (이번 구현)

```
오늘 한장
9월 27일 (일)

[ 이어서 — 어린이 영어 · ㄱ 3/8 ]
      오늘 한 장 시작

이번 주 도장  월 화 수 목 금 토 일

내 팩
  어린이 영어 · ㄱ        진행 중  >
  + 팩 추가               준비 중
```

- 자음 14개는 홈에 나열하지 않는다. 자음 목차는 팩 안(`/packs/[packId]`)에 둔다.
- 팩이 하나뿐인 지금은 "+ 팩 추가"를 누르면 준비 중인 팩 목록만 보여준다.

### 7-2. 팩 안 (어린이 영어)

```
어린이 영어 (한장영어)
ㄱ  3/8장
ㄱ ㄴ🔒 ㄷ🔒 ㄹ🔒 ㅁ🔒 …
끝낸 장: 01 02  (다시 보기)
```

### 7-3. 준비 중으로만 보여줄 팩

어린이 일본어, 성인 영어 출장, 성인 일본어. 중국어는 홈에 올리지 않는다.
준비 중 팩을 누르면 "나오면 알려주세요" 이벤트(`pack_interest`)를 기록한다. 2호 팩 순서를 정하는 근거로 쓴다.

## 8. 어린이 / 성인 스킨

`audience` 값으로 CSS 토큰과 카피만 바꾼다.

| | 어린이 | 성인 |
|---|---|---|
| 보상 | 도장 | 스트릭 · 이번 주 N장 |
| 글자 | 크게 (단어 32px↑) | 기본 |
| 그림 | 명확한 사물 | 아이콘·실사, 없으면 생략 |
| 요약 대상 | 부모 | 본인 |
| 하루 한도 | 팩별 2장 | 팩별 2장 |

성인 UI는 지금 만들지 않는다. 성공 기준은 **성인 샘플 JSON 1장이 같은 화면에서 깨지지 않고 렌더되는 것**이다. 이 샘플은 테스트용 fixture로만 두고 배포 목록에는 넣지 않는다.

## 9. 1호 팩 — 한장영어 (어린이)

기존 `한장영어_기획안.md`와 `한장영어_개발지시서.md`를 이 팩의 스펙으로 유지한다.

**대상:** 초3~4 · **목차:** 한글 자음 · **1차 출시:** ㄱ 8장 (콘텐츠 검수 완료, main 머지됨)

### 하루 루프

```
오늘 장 → 오늘의 소리 → 단어 8 → 전체 듣기 → 예문 2 → 퀴즈 5
→ 채점 → 오답 저장 → 도장 → 부모 요약
```

### 자음별 장 수

- ㄱㄴㄷㄹㅁ: 각 8장, 나머지: 각 5장
- ㄱ 8장을 가족이 끝내기 전에는 ㄴ을 만들지 않는다.
- 약점: 85장이면 약 4개월 분량이다. 구독 유지를 위해 2회차 트랙(같은 자음, 난이도 상향)을 ㅁ 이후에 설계한다.

### 잠금 규칙 (엔진 구현 완료)

- 같은 팩 안에서 장은 순서대로
- 팩별 하루 2장까지. 2장째는 직전 평일을 쉬었을 때만. 3장째부터 차단
- 평일에 활성 오답이 3개 이상이면 복습장. 주말은 복습장
- 오답이 3개 미만이면 다음 장의 5번 문항에 오답 단어 1개를 삽입
- 다음 자음은 현재 자음을 끝낸 뒤 열림

## 10. 2호 이후 팩 (예약만)

**성인 영어 · 출장 (2호 후보)**
상황 8장: 공항, 택시, 체크인, 미팅 시작, 전화 보류, 메일 한 줄, 식사, 작별.
아이템은 짧은 문장 8개(`kind: phrase`). 그림 문항은 5-5의 예외 규칙을 적용한다.

**일본어 · 여행 (3호 후보)**
`reading`(로마자 또는 한글 발음) 필드만 추가하면 된다. 중국어보다 먼저 연다.
어린이 일본어는 수요 근거가 약하다. `pack_interest` 데이터를 보고 순서를 정한다.

**중국어**
성조 필드가 필요하고 TTS 품질 확인도 필요하다. 세 번째로 연다.

## 11. 수익

팩 슬롯 구독. 가격을 어린이 앱 수준으로 고정하지 않는다.

### 무료

- 프로필 1개
- **팩 1개의 첫 단위 전체** (어린이 영어라면 ㄱ 8장)
- 부모/본인 요약: 오늘 요약만 (주간·약점 분석은 유료)

결제벽은 "다음 단위(ㄴ) 열기" 시점에 둔다. 이 시점이 곧 `next_pack_request` 이벤트이고, v1에서 정한 결제 타이밍과도 같다.

### 개인 구독 (가족 테스트 후 확정)

| 플랜 | 가격 | 포함 |
|---|---|---|
| 기본 | 월 9,900 / 연 79,000 | 프로필 1 × 팩 1 |
| 패밀리 | 월 14,900 / 연 129,000 | 프로필 3 · 팩 합계 3 |
| 추가 | +4,900 | 슬롯 1 (프로필 또는 팩) |

**슬롯 = 프로필 × 팩** 한 줄 기준으로 센다. 예: 아이 영어 + 부모 일본어 = 슬롯 2.

### 2차 이후

학원 반 라이선스(30명 월 49,000, 숙제 코드), 주간 인쇄 PDF, 화이트라벨.

### 초기에 하지 말 것

배너 광고, 코인/가챠, 무제한 AI 생성을 메인으로 내세우기, 언어마다 결제 상품 쪼개기.

수익의 본질은 **검수된 장 + 오답 데이터 + 슬롯을 늘릴수록 끊기 어려운 습관**이다.

## 12. 필수 화면

**학습자:** 오늘 홈 / 팩 안 목차 / 학습장 (소리·카드·듣기·예문) / 퀴즈 / 완료

**학습 중 닫기 (신규):**
- 모든 학습 단계 우측 상단에 ✕ 버튼 → "그만할까요? 처음부터 다시 해요" 확인 → 홈으로 이동
- 중간 진행은 저장하지 않는다. 한 장이 8분이라 처음부터 다시 해도 부담이 적다
- 닫기를 누르면 `sheet_abort`(단계, 경과 시간) 이벤트를 기록한다 → 어느 단계에서 이탈하는지 파악

**부모·본인 요약 (`/parent`):**
1. 오늘 완료 여부, 점수, 틀린 항목
2. 틀린 항목별 "내일 복습" 토글 (기본 ON)
3. 주간 도장/스트릭, 가장 많이 틀린 소리(tags 집계)
4. 내 팩 목록 (성인 팩이 생기면 여기에 함께)
5. 설정: PIN, 사용 기록 내보내기(JSON)

현재 라이브에는 `/parent`가 없다(404). **가족 테스트 시작 전에 반드시 있어야 한다.**

## 13. 데이터 모델

```text
Account      pin(hash), plan, slotLimit
Profile      accountId, type(child|self), name, grade?
Track        profileId, packId, status              // 슬롯 1개 = Track 1개
Attempt      profileId, packId, lessonId?, kind(lesson|review),
             dateKey, answers[{targetItemId, correct}], score,
             startedAt, finishedAt, completed
WrongQueue   profileId, packId, itemId, wrongCount,
             firstWrongDate, lastWrongDate, nextReviewDate, active
Event        profileId, type, dateKey, at, payload
```

- 현재 진도와 도장은 **저장하지 않고 Attempt에서 계산한다.** 두 곳에 저장하면 값이 어긋날 수 있다.
- WrongQueue에는 `packId`를 넣는다. 아이템 id는 팩 안에서만 고유하기 때문이다.
- MVP(가족 테스트)는 localStorage에 Account 1 · Profile 1(child) · Track 1로 저장하되, **구조는 위 모델 그대로** 둔다. 나중에 Prisma로 옮길 때 키 이름만 바꾸면 되게 한다.
- 서버 DB로 옮기는 시점에 만 14세 미만 법정대리인 동의 절차와 개인정보처리방침을 반드시 넣는다.
